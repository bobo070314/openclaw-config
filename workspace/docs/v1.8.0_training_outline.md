# v1.8.0 内部培训大纲

> **时长**: 10 分钟 · **受众**: 老板团队成员
> **前置**: 无，纯讲解

---

## 第 1 页：v1.8.0 是什么（2 分钟）

- 一句话：系统具备了"感知故障 → 分析原因 → 自动修复 → 验证成功"的闭环能力
- 核心资产：`scripts/auto_fixer.py`
- 灰度策略：先分析不动手（P0）→ 再补文件（P1）→ 再修配置（P2）→ 再恢复权限（P3）

## 第 2 页：三个修复策略（3 分钟）

| 策略 | 场景 | 示例 |
|---|---|---|
| S1 文件补全 | 文件丢失 | "No such file: configs/agent_chain.yaml" → 自动写模板 |
| S2 配置修正 | 语法错误 | "YAML parse error at line 12" → 重写配置 |
| S3 权限恢复 | RBAC 拦截 | "permission denied for user coder" → 恢复默认角色 |

## 第 3 页：安全边界（2 分钟）

- 修复恶化自动回滚：`post_repair_pass_rate < pre_repair_pass_rate` 触发
- 修复次数上限：单轮最多 2 次尝试
- 人工接管：检测到 `MANUAL_OVERRIDE` 文件立即停止所有自动修复
- 审计日志：每次修复写入 `violations.jsonl`

## 第 4 页：使用方式（2 分钟）

- 当前阶段：P0（仅分析），不影响现有流程
- 查看分析结果：`python scripts/auto_fixer.py`
- 独立演示：`python scripts/auto_fixer_demo.py`
- 查看模板：`S1_TEMPLATES` / `S2_TEMPLATES` / `S3_TEMPLATES`（代码末尾）

## 第 5 页：Q&A（1 分钟）

- 问：auto_fixer 会误修改文件吗？ → 答：P0 阶段只分析不执行。
- 问：如果 auto_fixer 修坏了怎么办？ → 答：`should_rollback()` 自动触发回滚。
- 问：我怎么知道它做了什么？ → 答：`violations.jsonl` 有完整的审计日志。
