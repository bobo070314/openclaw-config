# v2.0 Fault Expansion Request Template

> Submit new fault types here for protocol expansion.
> Fill in the template below. The fixer team will implement within one cycle.

## Fault Request Form

```yaml
fault_name: "<descriptive_name>"
fault_id: "<F-XXX>"
description: |
  <one-paragraph description of the physical or logical fault>

target_substrates:
  - "<silicon|lithium_anode|sic_wafer|electrolyte|custom>"

fail_reason_enum:
  - "<reason_A>"
  - "<reason_B>"

repair_strategies:
  S1: "<quick_fix_description>"
  S2: "<medium_fix_description>"
  S3: "<full_rollback_fix_description>"

expected_pass_rate_delta: "<+0.XX>"

escalation_rules:
  auto_fix: "<entropy_level|pass_rate_threshold>"
  manual_required: "<condition>"
```

## Example: F-001 Crack (already implemented)

```yaml
fault_name: "Silicon Substrate Crack"
fault_id: "F-001"
description: |
  Physical fracture on silicon negative electrode surface.
  Detected by vision system. Yield impact: 20-30%.

target_substrates:
  - silicon

fail_reason_enum:
  - "thermal_stress"
  - "mechanical_damage"
  - "material_purity"

repair_strategies:
  S1: "Thermal anneal at 450°C for 30 min"
  S2: "Localized laser repair + stress relief"
  S3: "Substrate replacement + root cause analysis"

expected_pass_rate_delta: "+0.18"

escalation_rules:
  auto_fix: "entropy_level <= NORMAL"
  manual_required: "entropy_level == CRITICAL or pass_rate_before < 0.5"
```

## Submission Process

1. Copy the YAML template above.
2. Fill in your fault details.
3. Submit via PR to `docs/specs/faults/` or email to fixer@silicon-body.com.
4. Protocol team reviews within 24h.
5. Once approved, the new fault type is live in the next release.
